# AlgoLatch v0.1.1-preview.3 for macOS and Windows

> **Testing prerelease:** this version changes the primary workbench from a
> canvas-first layout to a code-first C Cell workflow. Some lessons can still
> contain animation, interaction, responsive-layout, text-overlap,
> localization, or result defects.

This prerelease provides two unsigned packages built and verified from the same
source revision:

- `AlgoLatch-0.1.1-preview.3-unsigned-universal.dmg` for Apple Silicon and
  Intel Macs; and
- `AlgoLatch-Setup-0.1.1-preview.3-unsigned-x64.exe` for Windows 10/11 x64.

Download both the installer and `SHA256SUMS.txt` from this GitHub Release. The
automatically generated **Source code** archives are not installers.

## What changed

### C Cell is now the main workspace

- The center column opens on **C Cell** instead of the freeform canvas.
- Enter a complete C program, statement, or control block, then press
  **Cmd/Ctrl+Enter** or select **Run cell**.
- Every cell recompiles independently. A later cell cannot use variables or
  process state from an earlier cell.
- A selected case can provide input, and explicit inline `stdin` overrides the
  case for that submission.
- Bounded `stdout` and `stderr` stream directly under the submitted cell.
  Active runs can be cancelled with **Esc** or **Cancel run**.
- Compiler diagnostics for generated wrapper code map back to the user's C
  Cell instead of exposing only generated line numbers.

C Cell is not a persistent C REPL. This release does not include a System
Shell.

### Source authority remains unchanged

Statements and control blocks run inside a clearly labeled temporary wrapper.
That wrapper is collapsed by default and never changes the project by itself.

Selecting **Write to main.c** shows the complete candidate source and exact
diff. AlgoLatch writes only after the user confirms and the candidate passes
the existing revision, fingerprint, reparse, lossless-round-trip, and CFG
checks. Cancelling leaves the disk source unchanged.

### Semantic supervision stays beside the code

The right column now keeps these views close to the C Cell:

- **Flow** for the read-only control-flow projection;
- **Blocks** for the source-to-block projection;
- **Diagnostics** for compile and static findings;
- **AI** for the optional project assistant; and
- **Edit** for source-bound changes and exact-diff review.

While a user is typing incomplete C, Flow keeps the last valid projection and
shows a typing state instead of rebuilding around a broken partial tree. The
compact C Cell Flow view is read-only. The full canvas remains available as a
secondary workspace for controlled structural editing.

### Workspace and canvas reliability

- Workspace switching now detaches the old sidecar consumer before adopting
  the incoming source, preventing one file's view state from being written into
  another entry.
- The application stores only a versioned opaque ID for last-workspace resume.
  A missing or unreadable entry returns safely to the Dashboard.
- First-open projections fit the available view without overwriting a saved
  viewport.
- Canvas coordinates include scroll offsets, focus no longer moves the canvas
  unexpectedly, and the overview remains anchored to the lower-right corner.
- Flow sockets are visually smaller while retaining larger invisible hit
  targets. Structural controls appear progressively during pointer, selection,
  or keyboard interaction.
- Ordinary C that is not recognized as a named algorithm remains visually
  active. The UI still avoids claiming real reachability without Trace
  evidence.

### Run and Trace evidence

- Verified runs use bounded start/read/cancel sessions with ordered output
  events and terminal results.
- C Cell can start a real Trace, but Trace still proves executed lines and
  branches rather than arbitrary variable samples.
- C Cell's session history is isolated by workspace and source fingerprint. It
  does not enter the persistent project run history.
- C Cell and `main.c` expose one relevant run action at a time, avoiding
  competing controls.

## Known preview limitations

- The macOS app uses an ad-hoc signature. It is not Developer ID signed or
  notarized.
- The Windows installer is not Authenticode-signed. Windows can show an
  unknown-publisher or SmartScreen warning.
- Individual lessons can still have animation timing, interaction, text
  overlap, responsive layout, localization, task-validation, or result bugs.
- C Cell does not retain variables between submissions, and this release has no
  System Shell.
- The workbench remains a single-`main.c` application. Macros, `goto`, parser
  recovery, and partial CFG regions can reduce structured-editing capability.
- Some semantic scenes use bounded teaching models. They do not claim to be
  arbitrary runtime-variable sampling.

If you find a lesson issue, open a
[GitHub issue](https://github.com/Ice-teapop/algolatch/issues/new/choose) with
the lesson number, operating system, display scale, reproduction steps, and a
screenshot. Do not post private source code, API keys, or exploitable security
details in a public issue.

## Installation and verification

### macOS

1. Download the Universal DMG and `SHA256SUMS.txt`.
2. Run `shasum -a 256 --check SHA256SUMS.txt` in the download directory.
3. Open the DMG and copy **AlgoLatch** to **Applications**.
4. If Gatekeeper blocks this unsigned preview, Control-click the app, choose
   **Open**, and approve it once. Never disable Gatekeeper globally.

### Windows

1. Download the x64 EXE and `SHA256SUMS.txt`.
2. Verify the installer with `Get-FileHash` before opening it.
3. Run the one-click per-user installer. It does not require administrator
   access, an external compiler, a gateway script, or a `PATH` change.

Replacing or uninstalling AlgoLatch does not remove managed projects in
Documents. Back up important `main.c` files before changing application
versions.

## Release and rollback boundary

The release workflow publishes this prerelease only after the common gates and
both platform installed-state jobs pass. It creates one checksum manifest for
the final DMG and EXE and refuses to replace an existing tag or asset.

If `v0.1.1-preview.3` causes a blocking regression, stop using it and reinstall
[`v0.1.1-preview.2`](https://github.com/Ice-teapop/algolatch/releases/tag/v0.1.1-preview.2).
Managed projects stay in Documents, but keep a backup before moving between
preview versions. The immutable `v0.1.1-preview.2` tag and assets remain the
rollback point; no release asset is overwritten in place.
